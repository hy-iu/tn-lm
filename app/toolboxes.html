合并规则与核验方式 · 点击展开

张量分解 / 张量网络方向可直接上手的开源实现。条目取自两份社区维护的清单，但数字不是转抄的：star 数、许可证、最后推送时间与归档状态逐个向 GitHub 请求取得，能力描述同时给出清单原文与仓库自述，两者不一致时并列呈现而不替读者裁决。

合并规则：两份清单的 Software / Toolboxes 小节按工具名合并；同名但指向不同仓库的不合并 —— TenDeC++ 就是这种情况，两份清单各指一个不同的 C++ 项目，页面上用 owner 消歧，能力描述也各自独立，不互相借用。

核验：star / 许可证 / 最后推送 / 归档状态取自 GitHub REST 接口；配额耗尽时退回抓仓库页面，此时许可证一栏留空而不是猜一个。1 个条目没有 GitHub 仓库（只有 GitLab 或官网），按 HTTP 可达性判定。

分类：默认由源表的章节结构与「NN layers」列推出；quimb、cotengra、TorchMPS 三条推不准，在 lit/gen_toolboxes.py 的 CAT_OVERRIDE 里手工指定并写了理由。

不一致：清单描述与仓库自述冲突时两条都留着，不替读者裁决。例如 TeD-Q 被清单描述为「可微分量子机器学习与 TN 模拟」，而仓库自述说它是 TED-Q 数据集；google/TensorNetwork 已被 GitHub 标记为归档（只读），页面上打了标记而不是照抄清单的现在时描述。

分解格式速查

下表照录 Tensor Methods for LLMs 清单的 Tensor Formats 图例，用来解读上面「支持格式」一栏。物理命名与数值线性代数命名指的是同一批对象：MPS 就是 TT，MPO 就是 TTM。

格式含义
CP (Canonical Polyadic)sum of R canonical rank-one tensors
Tuckera dense core tensor contracted with one factor matrix per mode
TT (Tensor Train)a chain of third-order cores
TTM (Tensor Train Matrix)TT applied to a matrix with input and output modes paired
MPS (Matrix Product State)the physics name for TT
MPO (Matrix Product Operator)the physics name for TTM
BT (Block Term)sum of K Tucker terms
Kroneckermatrix written as a sum of R Kronecker products
